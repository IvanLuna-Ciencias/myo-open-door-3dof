# LabVIEW VI

This document describes the role of the LabVIEW VI included in the Myo Open Door 3DOF Demo.

The VI is used as the LabVIEW-side receiver for the setpoints generated by the Python script. It is included as a companion file for this demo, not as a complete standalone documentation of the full exoskeleton control architecture.

A dedicated repository for the full LabVIEW configuration and exoskeleton interface will be created later. This repository only documents the minimum LabVIEW integration required for the Myo-based UDP demo.

---

## 1. General Role

The LabVIEW VI receives real-time setpoints generated by the Python script.

The general communication flow is:

```text
Myo Armband -> Python script -> UDP packet -> LabVIEW VI
```

The Python script processes Myo IMU and EMG signals, estimates three upper-limb setpoints and sends them to LabVIEW through UDP.

The LabVIEW VI receives those setpoints and uses them as references for the local exoskeleton interface or visualization environment.

## 4. Input Message

The VI receives a comma-separated UDP message with three numeric values:

```text
q_shoulder_rad,q_elbow_rad,q_rot_rad
```

Each value is sent in radians.

The expected order is:

| Position | Variable | Meaning |
|---:|---|---|
| 1 | `q_shoulder_rad` | Shoulder flexion/extension setpoint |
| 2 | `q_elbow_rad` | Elbow flexion/extension setpoint |
| 3 | `q_rot_rad` | Shoulder/exoskeleton rotation setpoint |

The order must remain consistent between Python and LabVIEW.

---

## 5. UDP Configuration

The default UDP configuration used by the Python script is:

```text
Host: 172.22.11.2
Port: 5005
```

The LabVIEW VI must listen to the same UDP port.

If the IP address or port changes, update both sides consistently:

```text
Python LV_HOST / LV_PORT <-> LabVIEW UDP receiver
```

---

## 6. Expected VI Behavior

The LabVIEW VI should perform the following steps:

1. Open a UDP receiver.
2. Listen to the configured UDP port.
3. Read the incoming UDP string.
4. Remove the end-of-line character if necessary.
5. Split the string using commas.
6. Convert each string value to a numeric value.
7. Assign each value to the corresponding setpoint.
8. Use the setpoints in the local exoskeleton interface, controller or visualization.

The expected setpoint order is always:

```text
shoulder, elbow, rotation
```

---

## 7. Units

All setpoints are received in radians.

If the LabVIEW side requires degrees, use:

```text
degrees = radians * 180 / pi
```

Reference values:

| Radians | Degrees |
|---:|---:|
| 0.000000 | 0 deg |
| 0.174533 | 10 deg |
| 0.523599 | 30 deg |
| 0.785398 | 45 deg |
| 1.570796 | 90 deg |

---

## 8. Example Packet

Example UDP packet received by LabVIEW:

```text
0.523599,0.785398,-0.174533
```

This corresponds approximately to:

| Variable | Value |
|---|---:|
| `q_shoulder_rad` | 0.523599 rad |
| `q_elbow_rad` | 0.785398 rad |
| `q_rot_rad` | -0.174533 rad |

## 9. Synchronization Notes

The Python script sends active setpoints after the calibration routine is complete.

UDP does not guarantee packet delivery. For this demo, this is acceptable because the system continuously sends updated setpoints and the most recent packet is the most relevant.

If no packet is received before calibration, this is expected behavior.

---

## 10. Recommended LabVIEW Checks

Before running the demo, verify that:

- The VI is open.
- The UDP receiver is running.
- The UDP port matches the Python script.
- The LabVIEW computer IP matches the Python `LV_HOST` value.
- The firewall is not blocking UDP packets.
- The parser correctly separates the three values.
- The values are interpreted in radians.
- The setpoint order is shoulder, elbow and rotation.
- The Python script has completed calibration.

---

## 11. Common Problems

### LabVIEW does not receive data

Possible causes:

- The VI is not running.
- The UDP port is different in Python and LabVIEW.
- The IP address is incorrect.
- A firewall is blocking UDP packets.
- Python and LabVIEW are not connected to the same network interface.
- The Python script has not completed calibration.

### Values are received but look incorrect

Possible causes:

- LabVIEW is interpreting radians as degrees.
- The parser is using the wrong separator.
- The order of the setpoints is incorrect.
- The received string includes an unexpected character.
- The LabVIEW numeric conversion is not configured correctly.

### No values are received before calibration

This is expected.

The Python script starts sending active setpoints after the calibration routine is complete.
